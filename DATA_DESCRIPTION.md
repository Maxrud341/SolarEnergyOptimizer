# Описание данных SolarEnergyOptimizer

Ниже — краткая карта всех CSV-файлов проекта, чтобы дальше использовать их в моделях, оптимизации и визуализации без путаницы в единицах измерения.

## Общий вывод по единицам

- Мощность в исходных данных обычно измеряется в Вт: `W`
- Энергия в агрегированных/подготовленных данных измеряется в кВт·ч: `kWh`
- Температура — в °C
- Облачность — в %
- Скорость ветра — в m/s
- Направление ветра — в градусах (0–360°)
- Влажность — в %
- Цена электроэнергии — обычно в EUR/MWh или CZK/kWh, зависит от колонки
- Состояние батареи — в % (`SoC`) и в кВт·ч (`battery_kwh`)

## 1) [data/Maly.csv](data/Maly.csv)

Это сырой набор данных домашней электроустановки: солнечная батарея + аккумулятор + сеть + нагрузка дома.

### Частота данных
- Временной шаг: примерно 5 минут
- Формат времени: `YYYY-MM-DD HH:MM:SS`

### Ключевые колонки

| Колонка | Описание | Единица |
| --- | --- | --- |
| `ID_zaznamu` | ID записи | — |
| `ID_ZDROJE` | ID источника/системы | — |
| `DatumCas` | дата и время замера | datetime |
| `SoC` | состояние заряда аккумулятора | % |
| `P_PV` | мощность солнечной панели | W |
| `P_HOME` | общая потребляемая мощность дома | W |
| `P_HOME_L1/L2/L3` | нагрузка по фазам | W |
| `P_EPS` | мощность/потребление EPS | W |
| `P_GRID` | мощность обмена с сетью | W |
| `P_GRID_L1/L2/L3` | обмен с сетью по фазам | W |
| `P_BAT` | мощность батареи | W |
| `PVenergy` | энергия, произведённая/учтённая по PV | вероятно Wh или часть кВт·ч для интервала |
| `PVenergy_T` | накопительная сумма по PV | тот же тип единицы, что и `PVenergy` |
| `ToBAT` | энергия, отправленная в батарею | вероятно Wh/интервал |
| `ToBAT_T` | накопительная сумма в батарею | тот же тип единицы |
| `FromBAT` | энергия, взятая из батареи | вероятно Wh/интервал |
| `FromBAT_T` | накопительная сумма из батареи | тот же тип единицы |
| `SELL` | проданная энергия | вероятно Wh/интервал |
| `SELL_T` | накопительная сумма продажи | тот же тип единицы |
| `BUY` | купленная энергия | вероятно Wh/интервал |
| `BUY_T` | накопительная сумма покупки | тот же тип единицы |
| `Consumed` | потреблённая энергия | вероятно Wh/интервал |
| `Consumed_T` | накопительная сумма потребления | тот же тип единицы |
| `GRID_LIMIT` | лимит по сети | W или ограничение мощности |

### Важное замечание по единицам

Здесь есть два типа данных:

1. `P_*` — это мощность, то есть Вт (`W`)
2. `*_T` и многие `*_energy` поля — это энергия за интервал или накопительная энергия; чаще всего это либо `Wh`, либо `kWh` в зависимости от масштабирования

По значениям в файле видно, что мощность имеет порядок нескольких тысяч ватт, например:
- `P_PV ≈ 2000–5000 W`
- `P_HOME ≈ -600 ... +2000 W`

А что касается энергии: значения в этой таблице выглядят как промежуточные суммарные данные, поэтому перед моделированием их лучше приводить к единому формату `kWh`.

### Что важно для задачи

- Аккумулятор, вероятно, около 0.5 кВт·ч, так как в подготовленных данных `battery_kwh` находится в диапазоне примерно `0.43–0.48`
- Отрицательные значения `P_HOME` / `P_GRID` часто означают направление потока энергии, а не ошибку

## 2) [data/ceny.csv](data/ceny.csv)

Это цена электроэнергии на бирже/рынке.

### Частота данных
- Временной шаг: 1 час
- Формат времени: `YYYY-MM-DD HH:MM:SS`

### Колонки

| Колонка | Описание | Единица |
| --- | --- | --- |
| `DatumCasOTE` | время цены | datetime |
| `CenaEUR` | цена в евро | вероятно EUR/MWh |
| `CenaCZK` | цена в чешских кронах | вероятно CZK/kWh |

### Что видно по данным

Примеры:
- `101.9` в `CenaEUR`
- `2.54` в `CenaCZK`

Это очень похоже на:
- `CenaEUR` = цена в EUR/MWh
- `CenaCZK` = цена в CZK/kWh

То есть численно они согласуются после перевода курса EUR/CZK.

### Важное замечание

Для оптимизации модели цена должна быть приведена к единой единице, например:
- `EUR/kWh`, либо
- `CZK/kWh`

Иначе легко получить ошибочные расчёты по стоимости энергии.

## 3) [data/predpoved.csv](data/predpoved.csv)

Это прогноз погоды для солнечной генерации.

### Частота данных
- Временной шаг: 1 час
- Формат времени: `YYYY-MM-DD HH:MM:SS`

### Колонки

| Колонка | Описание | Единица |
| --- | --- | --- |
| `ID_ZDROJE` | ID источника прогноза | — |
| `DatumCas` | дата и время прогноза | datetime |
| `Teplota` | температура | °C |
| `Oblacnost` | облачность | % |
| `Vitr` | скорость ветра | m/s |
| `Smer` | направление ветра | градусы (0–360°) |
| `Vlhkost` | влажность | % |

### Примечание

Значения выглядят как реальные метеоданные на каждый час, с диапазоном температуры около 5–13°C, а облачность — 30–100%.

Это подходит для моделирования выработки PV и оценки влияния погоды на солнечную генерацию.

## 4) [data/sun.csv](data/sun.csv)

Это предполагаемая выработка солнечной панели.

### Частота данных
- Временной шаг: 1 час или интервальный шаг, похожий на прогнозную производительность
- Формат времени: `YYYY-MM-DD HH:MM:SS`

### Колонки

| Колонка | Описание | Единица |
| --- | --- | --- |
| `ID_ZDROJE` | ID записи | — |
| `DatumCas` | дата и время | datetime |
| `Vyroba` | выработка за интервал | вероятно Wh или kWh |
| `Suma` | накопленная сумма выработки | тот же тип единицы, что и `Vyroba` |

### Что видно по значениям

Например:
- `Vyroba = 224`, затем `562`, `890`, `1123` ...
- `Suma = 224`, `816`, `1706`, `2829`, ...

Такой рост выглядит как накопленная солнечная генерация за период дня, где значения имеют порядок несколько тысяч, то есть примерно 2–5 кВт·ч за час в пиковые моменты. Это соответствует солнечной панели.

### Важная оговорка

Поле `Vyroba` пока лучше считать как:
- либо энергия за период в `Wh`,
- либо в `kWh`,

но для дальнейших расчетов желательно привести все значения к единому формату и явно проверить масштаб.

## 5) [data/datasource.csv](data/datasource.csv)

Это уже подготовленный/очищенный источник данных для моделирования. Здесь единицы измерения уже согласованы.

### Колонки

| Колонка | Описание | Единица |
| --- | --- | --- |
| `datetime` | дата и время | datetime |
| `consumption_kwh` | потребление дома | kWh |
| `production_kwh` | производство PV | kWh |
| `battery_kwh` | уровень заряда аккумулятора | kWh |

### Пример проверки

В первых строках:
- `consumption_kwh ≈ 0.052`
- `production_kwh ≈ 0.193`
- `battery_kwh ≈ 0.43`

Это очень хорошо согласуется с предположением, что аккумулятор имеет ёмкость примерно 0.5 кВт·ч.

### Почему это главный файл

Если планируются модели оптимизации и предсказания, то именно [data/datasource.csv](data/datasource.csv) — самый безопасный и единообразный источник данных, потому что все колонки уже в `kWh`.

## Рекомендация по дальнейшей работе

Для стабильной работы лучше использовать следующий порядок:

1. Основной рабочий набор: [data/datasource.csv](data/datasource.csv)
2. Проверка погодных факторов: [data/predpoved.csv](data/predpoved.csv)
3. Проверка цены: [data/ceny.csv](data/ceny.csv)
4. Сырые инженерные данные: [data/Maly.csv](data/Maly.csv)
5. Прогноз выработки: [data/sun.csv](data/sun.csv)

### Практическая рекомендация по конвертации

- Все значения мощности приводить к `W`
- Все значения энергии приводить к `kWh`
- Все цены привести к `EUR/kWh` или `CZK/kWh`
- Аккумулятор хранить как `kWh`
- Состояние батареи `SoC` хранить отдельно как процент, а не путать с `battery_kwh`
